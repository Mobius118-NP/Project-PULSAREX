# Reliability audit and instrument presentation — v0.2.0

The four-layer architecture remains acquisition → DSP/interpretation → application server/storage → dashboard. The visual change is isolated in a CSS presentation layer. No target identity, motion or real bearings are invented.

## Fixed

- Threshold/reference controls restarted capture and cleared histories. These controls now update in place under serialized lifecycle controls.
- Simultaneous configuration requests could lose each other's changes. Lifecycle operations now use a separate control lock.
- Pause, reconnect and dropped blocks could leave temporal associations or mixed FFT windows. Streams now have unique IDs and sample sequence discontinuities reset the analysis window.
- Stopped or failed input could leave valid-looking measurements. Current estimates now carry freshness metadata and become unavailable on stale input or link loss.
- Calibration counted time without audio. It now counts contiguous acquired intervals and pauses across gaps.
- Baseline adaptation accepted large negative or narrow-band deviations. It now checks absolute deviations, and adapted profiles are persisted periodically/on stop.
- Corrupt baseline files or persistence failures could stop analysis. Invalid profiles are ignored; write failures become visible warnings.
- A fixed 0.5-second read timeout failed for valid long-hop configurations. Capture waits now respect the configured period and remain cancellable.
- A hung native driver could prevent switching inputs. Native capture is isolated in a bounded worker process with cancellable startup, timeout and forced cleanup.
- Automatic WASAPI selection could retain a mismatched sample rate. Device inventory now identifies the automatic input and its native format; the UI applies that rate on selection.
- Microphone errors lacked direct recovery controls. Refresh/retry/switch controls now stay available during input faults.
- Changing devices could retain geometry belonging to another array. Geometry is invalidated unless explicitly configured again.
- Harmonic candidates depended on peak amplitude order and could count duplicate harmonic orders. Grouping now considers frequency order and unique orders.
- Narrowband input could produce misleadingly confident GCC-PHAT bearings. Such estimates are now explicitly unavailable; residual inconsistency reduces confidence.
- Sample-rate round trips permanently narrowed the display band. The configured analysis ceiling is preserved across temporary lower-rate operation.
- Other dashboard clients could keep obsolete settings. Snapshots now carry configuration revisions and authoritative settings.
- Spectrogram duration used nominal update frequency. It now uses measurement timestamps, and repeated paused snapshots are excluded.
- The event archive rebuilt up to 5,000 rows every two seconds. Monitoring now fetches five recent events, with archive pages loaded on demand.
- Malformed hosts/origins caused server errors, logout did not revoke replayed cookies, and login attempts were unlimited. These cases are handled with validated parsing, expiring/revocable bounded sessions and a bounded login-attempt limiter.
- The launcher opened the browser before readiness and ignored config.toml. It now waits for a ready server and uses the local configuration when present.

## Validation

The regression suite covers the above failure paths with synthetic signals, fake microphones, a hung process double, invalid-device worker startup and real REST/WebSocket test clients. No physical audio is recorded by tests. Browser verification exercised visible input-fault recovery controls, settings access during faults, transition to simulation, pause invalidation and resume.

Physical microphone compatibility and recovery after actual hardware unplugging still depend on the Windows driver and should be checked in the normal user session. This audit does not claim exhaustive absence of defects.
