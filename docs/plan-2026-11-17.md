# PULSAREX incremental upgrade

## Audit

The clean v0.2.0 checkout already implements separated acquisition (`audio.py`),
DSP (`dsp.py`), orchestration (`engine.py`), persistence (`storage.py`), server
(`server.py`) and packaged dashboard assets. Preserve these boundaries and the
existing olive instrument theme and continuous signed frequency-shift gradient.
Native input isolation, bounded queues, reconnect continuity, same-origin checks,
LAN authentication and synthetic tests are working features to retain.

Missing: robust initialization and variation-aware detection, automatic initial
learning, multiple profiles, narrow-tone sensitivity, completed-event duration,
review/signature memory, versioned APIs/OpenAPI, stereo validation, independent
ARGOS/sensor adapters, discovery, client endpoint recovery and executable build.
Mean/variance calibration and the changed-display-bin fraction are insufficient
for the requested fan-plus-new-tone scenario. There is no validated sound classifier.

## Sequence and validation gates

1. Audit and run the existing suite with a workspace temporary directory (the
   default Windows pytest temporary directory has an existing permissions error).
2. Robust baseline: bounded calibration reservoir, median/MAD, slow time-based
   gated adaptation, freeze/reset, profiles, full FFT-bin detection. Synthetic fan,
   additions, disappearance, speed changes and drift tests before integration.
3. Event lifecycle, review annotations, compact human-reviewed signatures and
   SQLite migration compatible with existing JSON events. Persistence tests.
4. Preserve dashboard and add profile, anomaly, band-energy, review and network
   controls, baseline/deviation overlays. Validate JS and browser rendering.
5. Independent optional ARGOS observations/FOV, sensor and stereo adapters;
   authenticated versioned APIs and WebSocket aliases. API and ambiguity tests.
6. Optional mDNS and identity-checked endpoint selection. Public serving stays
   disabled: this checkout has no deployed TLS proxy or reviewed public perimeter.
7. Profile bounded operation; select and build PyInstaller distribution, smoke-test
   it outside the virtual environment; document what requires physical hardware,
   another LAN device, external ARGOS and a clean Windows machine.

No source identity, speech transcription, distance or confirmed motion claims.
No automatic cloud deployment, firewall changes or router configuration.

## Completed gates

- Original audit: 61 tests passed after selecting a writable temporary directory.
- Robust baseline/DSP synthetic gate: 34 tests passed before full integration.
- Event/profile and initial integration gate: 70 tests passed.
- Versioned API/stereo/endpoint recovery gate: 76 tests passed.
- Security, nonfinite payload, bounded writer, interrupted streams and range-boundary
  gate: final 81 tests passed.
- Local browser: instruments, profile freeze/save, event review/signatures, stop
  validity, 390 px responsive width and empty final error log verified.
- PyInstaller build and outside-venv smoke test completed; final release rerun and
  measured artifact results are documented in validation.md.
- Performance and multi-resolution investigation recorded, with scientific and
  hardware validation limits in acoustic-model.md/features.md.

Automatic profile transition suppression, full acoustic classification, simultaneous
live multiresolution fusion and public serving remain explicitly deferred research/
deployment work. The adapters and packaged build do not validate external hardware.
